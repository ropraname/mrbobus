## Следующий этап

1. Сверить симптомы физической езды с записью телеметрии. Мини-ПК пока исключён по указанию пользователя.
2. Принято направление: `odrive_ros2_control` + стандартный `diff_drive_controller`, не standalone `odrive_node`. Основные velocity/encoder сообщения совпадают с0.5.6; требуется ограниченная адаптация и проверка конкретных отличий, а не новая самописная кинематика. Подробности ниже.

4. Сверить фактический TF L2, его yaw, положение, временные поля облака/IMU. Уже существующий URDF уточнять, не создавать второй параллельный.
5. Записать rosbag и проверить ROS2 LIO на Pi5 4GB (мини-ПК не используется). Официальный Unitree Point-LIO основан на ROS1, установка на Jazzy требует проверенного порта. Разделить LIO-одометрию и повторную локализацию в сохранённой карте; избежать двух владельцев odom→base_link.
6. После устойчивой езды и локализации — карта препятствий/планирование, затем семантика и соревнование.

## Конкретные отличия официального ODrive-плагина

Исследован `ros_odrive` commit `efe8f775f1c1ef1aec4dd23f6f8b2ccdd5239652`.

- `read_nonblocking()` читает уже пришедшие кадры, не отправляет RTR. Живой пассивный замер3s подтвердил по300 кадров0x09 от каждой оси: циклическая телеметрия100Hz уже настроена. Во время Idle оценки0x09 нулевые; движение/масштаб этих оценок ещё проверить, текущая нода использует raw Hall0x0A.
- `write()` повторяет setpoint в каждом цикле, преобразуя rad/s↔turn/s через2π. Таймаут `cmd_vel` должен оставаться на уровне diff_drive_controller; hardware watchdog страхует остановку процесса, а не зависший источник, пока controller_manager продолжает слать старую команду.
- В исследованном плагине heartbeat/error handling отсутствует, возраст encoder feedback не проверяется; TODO прямо в upstream README. Нужно передавать потерю оси/устаревшую обратную связь в controller_manager и останавливать все4 колеса.
- 0x1C нельзя декодировать как torque на0.5.6 (там ADC). Не экспортировать фиктивную torque-телеметрию.
- Учесть знаки левых/правых осей симметрично для setpoint и feedback; текущий URDF задаёт физическое положительное вращение вперёд.
- Проверить реакцию на CAN TX overflow и корректные lifecycle deactivate/shutdown, чтобы остановка контроллера не оставляла оси активными. Проверить vcan перед заменой рабочего сервиса.

## Как повторить проверку mock на Pi

В первом терминале (никакого CAN-драйвера этот запуск не содержит):

```sh
source /opt/ros/jazzy/setup.bash
source /home/taras/robot/mrbobus_ws/install/setup.bash
export ROS_DOMAIN_ID=43 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
unset CYCLONEDDS_URI
ros2 launch mrbobus_bringup control_mock.launch.py
```

Во втором терминале с тем же окружением: `python3 tools/test_control_mock.py` из локальной копии репозитория. Скрипт проверяет domain43 и наличие именно GenericSystem перед отправкой тестовых команд. После теста остановить launch черезCtrl-C.
