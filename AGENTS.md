# Работа с mrbobus

- Текущий этап: надёжное управление четырьмя мотор-колёсами и локализация по Unitree L2. Задание соревнования и LLM — следующий этап.
- Начинай с README.md и docs/status.md. Различай живую проверку, свидетельство Тараса и предположение из CAD.
- Исходники ROS находятся в src/, конфигурация развёртывания в deploy/, диагностические утилиты в tools/. Не добавляй build/install/log, rosbag, расшифровки с секретами и CAD-экспорты в Git.
- Исходное состояние с Pi сохранено в .local/baselines/; никогда не коммить пароли, ключи и файлы robot/secrets.
- На роботе один владелец CAN. Не запускай второй управляющий процесс рядом с robot-base. Диагностические запросы CAN тоже могут кормить watchdog старой прошивки.
- Перед изменением работающего робота сохраняй исходники и конфиги. Изменения сначала проверяй локально и на vcan. Не включай моторы и не запускай калибровку как побочный эффект диагностики.
- Проверяй CAN по прошивке ODrive 0.5.6; современный ros_odrive не совместим с 3.x без адаптации. Не подменяй старые сообщения новыми.
- Не дублируй владельцев TF. Сейчас robot_base публикует odom→base_link, URDF — base_link→unilidar_lidar, драйвер L2 — unilidar_lidar→unilidar_imu.
- Размеры/TF датчика из CAD предварительные, пока не проверены физически. Не обещай готовую локализацию по одному наличию облака точек.
- Обновляй docs/status.md при существенном изменении; не плодить отчёты о каждом запуске.
